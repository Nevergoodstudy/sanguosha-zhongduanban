## P0 — 致命问题（立即修复）

### P0-1: time.sleep() 阻塞 Textual/asyncio 事件循环
- **位置**: `game/game_controller.py` 多处
- **描述**: 在AI延迟等场景使用 `time.sleep()`，直接阻塞Textual的asyncio事件循环
- **影响**: UI冻结，无法响应用户输入，程序表现为无响应
- **根因**: 混合同步/异步代码，未使用asyncio原生的非阻塞等待
- **参考**: asyncio官方文档明确禁止在事件循环线程中使用阻塞调用
- **严重度**: ★★★★★ — 直接导致TUI不可用

### P0-2: raw input() 绕过 UI 抽象层
- **位置**: 多处（需全面排查）
- **描述**: 使用Python内置 `input()` 函数获取用户输入
- **影响**:
  - 在Textual TUI模式下，input()会阻塞事件循环
  - 在网络模式下，input()在服务器端无意义
  - 破坏了UI层的抽象
- **根因**: 早期开发时的临时方案未被替换
- **参考**: Textual框架要求所有用户交互通过Widget完成
- **严重度**: ★★★★★ — 破坏多模式兼容性

### P0-3: 技能转换机制仅对AI生效，人类玩家无法使用
- **位置**: `game/combat.py` lines 155, 184, 195
- **描述**: 龙胆（赵云）和武圣（关羽）等转换技能使用 `player.is_ai` 检查
- **影响**:
  - 人类玩家无法使用核心武将技能
  - 严重破坏游戏平衡（人类比AI弱）
  - 与三国杀OL规则不符
- **根因**: 设计时未统一AI/人类玩家的技能触发路径
- **参考**:
  - 三国杀OL: 武圣可将所有红牌当杀使用，不区分人机
  - FreeKill: 技能通过统一的触发器机制发动
- **严重度**: ★★★★★ — 核心游戏机制错误

### P0-4: WebSocket Origin 验证默认禁用
- **位置**: `net/security.py` line 158
- **描述**: `OriginValidator` 默认 `allowed_origins=["*"]`，允许所有来源
- **影响**:
  - 跨站WebSocket劫持(CSWSH)风险
  - 任何网页可以连接游戏服务器
  - 可被用于DoS攻击
- **根因**: 开发阶段的便利配置未在生产前修正
- **参考**: websocket.org安全指南: "Always validate the Origin header during the handshake phase"
- **严重度**: ★★★★★ — 安全漏洞

### P0-5: 游戏引擎Facade过度耦合导致不可测试
- **位置**: `game/engine.py`
- **描述**: GameEngine.__init__ 167行，直接实例化9个子系统，所有子系统紧密耦合
- **影响**:
  - 无法独立测试任何子系统
  - 添加新功能需要修改核心类
  - 违反单一职责原则和开放/封闭原则
- **根因**: Facade模式被过度使用，变成了God Object
- **参考**: RFTG架构严格分离Game Model/Engine/Interface
- **严重度**: ★★★★☆ — 架构级障碍

## P1 — 严重问题（短期修复）

### P1-1: Engine保留伤害/濒死/死亡逻辑，未下放到CombatSystem
- **位置**: `game/engine.py`
- **描述**: 伤害、濒死、死亡处理逻辑仍在Engine中，与CombatSystem职责重叠
- **影响**:
  - 逻辑分散，修改一个流程需要两处同步
  - 结算顺序可能不一致
- **参考**: 三国杀OL: 死亡技能结算先于身份奖惩，需要严格顺序控制

### P1-2: 服务器GameLogic未实现，engine引用未初始化
- **位置**: `net/server.py`
- **描述**: GameServer有room管理框架，但game_engine引用始终为None
- **影响**: 网络多人模式完全不可用
- **参考**: FreeKill服务器提供完整的游戏逻辑 + 断线重连 + 录像回放

### P1-3: EventBus同步执行，不支持异步handler
- **位置**: `game/events.py`
- **描述**: 50+事件类型，所有handler同步执行，无异步支持
- **影响**:
  - 网络模式下无法使用await发送消息
  - 事件处理器内部触发新事件时可能导致顺序问题
  - 无法实现异步UI更新
- **参考**:
  - pygame wiki: EventManager的A,C,B vs A,B,C顺序问题
  - pytransitions: AsyncMachine支持异步回调

### P1-4: 无断线重连机制
- **位置**: 网络层全局
- **描述**: 玩家断线后无法恢复游戏状态
- **影响**: 网络对局中任何玩家掉线即导致游戏无法继续
- **参考**: FreeKill框架级提供断线重连和录像回放功能

### P1-5: 距离检查存在TOCTOU竞争条件
- **位置**: `game/combat.py` 距离检查逻辑
- **描述**: 检查攻击距离和实际执行攻击之间可能状态已变
- **影响**: 在多人异步场景下可能出现非法攻击

### P1-6: 技能使用硬编码限制为3个
- **位置**: `game/skill.py`
- **描述**: 每个武将技能数量硬编码上限
- **影响**:
  - 无法实现觉醒技（改变技能组）
  - 无法实现双将模式
  - 与三国杀OL不符（部分武将3+技能）
- **参考**: 三国杀OL: 武将技能数量不固定（标准版1-3个，觉醒后可变）

### P1-7: 巨型if/elif卡牌路由
- **位置**: `game/card_resolver.py` 或相关文件
- **描述**: 卡牌效果处理使用大量if/elif分支
- **影响**:
  - 添加新卡牌需要修改核心分发逻辑
  - 违反开放/封闭原则
- **参考**: 数据驱动设计: 卡牌效果应由注册表分发

### P1-8: action_log 初始化不可靠
- **位置**: `game/game_controller.py`
- **描述**: 游戏操作日志初始化时机和条件不稳定
- **影响**:
  - replay功能不可靠
  - 调试困难
  - 断线重连无法基于日志恢复

### P1-9: 缺乏完整的回合阶段状态机
- **位置**: `game/game_controller.py`
- **描述**: 回合阶段（准备→判定→摸牌→出牌→弃牌→结束）通过方法调用链实现，非形式化状态机
- **影响**:
  - 无法在任意阶段暂停/恢复
  - 无法正确处理跳过阶段的技能（如乐不思蜀跳过出牌阶段）
  - 状态转换无验证
- **参考**:
  - python-statemachine: 声明式状态机，守卫条件
  - gameprogrammingpatterns.com: FSM是游戏阶段管理的标准方案

### P1-10: DSL技能系统不完整，Python fallback为主
- **位置**: `game/skill.py`
- **描述**: 项目设计了DSL-first + Python fallback方案，但实际DSL覆盖率低
- **影响**:
  - 技能逻辑分散在DSL和Python代码中
  - 新增武将需要编写Python代码而非数据定义
  - 不利于社区贡献
- **参考**: FreeKill: Lua脚本定义所有技能，注册触发器

## P2 — 中等问题（中期优化）

### P2-1: 无TLS/WSS支持
- **位置**: `net/server.py`, `net/client.py`
- **描述**: 网络通信明文传输
- **影响**: 数据可被嗅探，不安全

### P2-2: 缺乏消息大小限制和验证
- **位置**: 网络层
- **描述**: 未配置WebSocket消息大小限制
- **影响**: 内存耗尽攻击风险

### P2-3: TUI测试覆盖不足
- **位置**: `tests/`
- **描述**: 1256测试/75.71%覆盖，但TUI交互测试和快照测试不明
- **影响**: UI回归难以检测
- **参考**: Textual Pilot API + pytest-textual-snapshot

### P2-4: 技能交互测试不足
- **位置**: `tests/`
- **描述**: 缺乏技能组合、边界条件、多技能同时触发的测试
- **影响**: 技能交互bug难以发现

### P2-5: 缺乏武将平衡性验证工具
- **描述**: 无自动化工具模拟大量对局并统计各武将胜率
- **影响**: 游戏平衡性依赖人工判断

### P2-6: i18n实现可能不完整
- **位置**: `i18n/`
- **描述**: 国际化框架存在但覆盖度需要验证
- **影响**: 非中文用户体验受限

### P2-7: 缺乏游戏状态快照能力
- **描述**: 无法在任意时刻捕获完整游戏状态
- **影响**: 无法实现断线重连、回放、保存/加载

### P2-8: 规则优先级系统未形式化
- **描述**: 三国杀核心规则"武将技能 > 游戏牌效果 > 基本规则"未在代码中形式化
- **影响**: 复杂技能交互可能违反规则
- **参考**: 萌娘百科: 明确规定了规则优先级体系

## P3 — 轻微问题（长期改进）

### P3-1: 缺乏性能基准测试
- **描述**: 无大规模并发测试（如100+同时对局）

### P3-2: 文档与代码不同步
- **描述**: docs/目录文档可能落后于代码

### P3-3: 缺乏CI/CD集成
- **描述**: 无自动化构建/测试/部署流水线

### P3-4: 缺乏扩展包加载机制
- **描述**: 武将和规则缺乏模块化加载
- **参考**: FreeKill: git-based扩展包管理

### P3-5: AI难度梯度可能不足
- **描述**: 3-tier(Easy/Normal/Hard)策略模式，但各层次差异需要验证
- **参考**: 三国杀OL: AI需要理解身份猜测、手牌记忆等高级策略
