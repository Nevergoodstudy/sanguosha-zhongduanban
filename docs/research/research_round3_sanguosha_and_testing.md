# 第三轮研究：三国杀OL游戏机制、开源实现与测试策略

## 研究时间
2026-02-19

## 研究范围
三国杀OL游戏机制、QSanguosha/FreeKill开源架构、武将技能系统设计、卡牌游戏测试策略

---

## 1. 三国杀OL核心游戏机制

### 1.1 游戏基础规则（来源：百度百科、萌娘百科）
- **身份系统**：主公、忠臣、反贼、内奸 — 隐藏身份猜测机制
- **胜利条件**：
  - 主公死亡 → 若仅内奸存活则内奸胜，否则反贼胜
  - 所有反贼和内奸死亡 → 主公和忠臣胜
- **回合阶段**：准备→判定→摸牌→出牌→弃牌→结束
- **规则优先级**：武将技能 > 游戏牌效果 > 基本规则

### 1.2 技能系统设计哲学（来源：知乎、萌娘百科）
- **早期（标准版+风火林山）**：技能描述20字以内，面杀友好
- **中期（一将成名系列）**：开始出现复杂表述和标记化
- **后期（2022+）**：出现"记录"功能，技能完全依赖程序实现
- **设计原则**：
  - 技能应呼应武将个性和历史事件
  - 需要考虑与已有武将的生克关系
  - 需要适配所属阵营和扩展包特性

### 1.3 卡牌类型体系
- **基本牌**：杀、闪、桃
- **锦囊牌**：
  - 非延时：无中生有、南蛮入侵、万箭齐发、决斗等
  - 延时：乐不思蜀、兵粮寸断、闪电
- **装备牌**：武器（攻击距离+特效）、防具、+1/-1马
- **转换规则**：如武圣将红牌当杀、龙胆杀闪互换

### 1.4 阵营设计特色（来源：知乎分析）
- **魏国**：反噬/卖血流（曹操掉血收牌、司马懿偷牌、郭嘉抽牌、夏侯惇弹伤）
- **蜀国**：仁义/配合（刘备仁德分牌、诸葛亮观星排牌）
- **吴国**：制衡/换牌流（孙权制衡、周瑜反间）
- **群雄**：独立/搅局（吕布无双、貂蝉离间）

### 1.5 对本项目的意义
- 项目已实现20+武将，但技能覆盖度和正确性需要验证
- 转换技能（武圣/龙胆）只对AI生效是P0级bug
- 需要完整实现三国杀的回合阶段系统
- 需要正确实现规则优先级系统

## 2. 开源三国杀实现参考

### 2.1 QSanguosha（太阳神三国杀）
- **技术栈**：C++ + Qt图形视图框架 + Lua(AI+扩展)
- **架构特点**：
  - Qt图形视图框架作为游戏引擎
  - FMOD声音引擎
  - Freetype字体渲染
  - Lua作为AI和扩展脚本语言
  - 支持键盘快捷键、拖拽使用卡牌
- **扩展性**：开放Lua扩展接口，允许自定义武将和模式
- **历史意义**：第一个完整复刻三国杀OL的开源项目

### 2.2 FreeKill（新月杀）
- **技术栈**：Qt C++ (底层) + Lua (游戏逻辑+房间调度) + Qt Quick (GUI)
- **架构特点**：
  - 性能优秀的单线程异步服务端（Lua实现）
  - 框架提供断线重连、录像与回放
  - 基本的游戏大厅功能
  - 支持Linux/Mac/Windows/Android/FreeBSD
- **DIY框架**：目标是提供最适合DIY的框架
- **技能定义方式**：
  ```lua
  local new_general = {
    name = "新武将",
    skills = {{
      name = "新技能",
      trigger = function(self, event, target, data)
        -- 技能逻辑
      end
    }}
  }
  game:registerGeneral(new_general)
  ```
- **生态系统**：扩展包仓库、武将编辑器、卡牌生成器

### 2.3 对本项目的启发
1. **Lua脚本化**：FreeKill用Lua实现所有游戏逻辑，Python也可类似
2. **断线重连**：FreeKill已实现，本项目缺失（P1-4）
3. **录像回放**：FreeKill框架级支持，本项目main.py有replay模式但需验证
4. **扩展包系统**：模块化武将和规则加载
5. **触发器机制**：技能通过event+trigger注册，非硬编码

## 3. 三国杀技能系统深层设计

### 3.1 技能触发时机体系
- **准备阶段**：某些技能在此发动
- **判定阶段**：延时锦囊判定（后放先判）
- **摸牌阶段**：如英姿(多摸一张)
- **出牌阶段**：主动技能
- **弃牌阶段**：如制衡(弃牌摸牌)
- **结束阶段**：如惠民(摸X张牌)
- **受伤时**：如反馈(偷牌)、遗计(抽牌)
- **濒死时**：桃、酒
- **死亡时**：如行殇(收取手牌)

### 3.2 技能分类
- **锁定技**：自动发动，不可选择
- **主公技**：仅主公可用
- **限定技**：一局只能用一次
- **觉醒技**：满足条件后永久改变
- **转换技**：将一种牌当另一种用（武圣、龙胆）

### 3.3 复杂技能交互规则
- 体力流失优先级高于任何技能
- 死亡技能结算先于身份奖惩
- 转变牌的使用者不会转变使用次数
- 判定区不能有两张同名延时锦囊

### 3.4 对本项目的意义
- 技能触发时机系统需要完整的事件钩子
- 当前EventBus的50+事件类型需要覆盖所有触发时机
- 技能分类系统需要正确实现（当前仅限3个技能P1-6）
- 复杂交互规则需要严格的结算顺序

## 4. 游戏平衡与设计原则

### 4.1 平衡性经验（来源：知乎分析）
- 标准版平衡性设计相当不错，四势力特点分明
- 一将成名系列开始出现强度不均
- 后期武将技能过于复杂，破坏新手友好性
- "表述复杂化"和"标记化"增加了编程实现的依赖

### 4.2 武将设计准则（来源：知乎DIY指南）
- 技能要对面杀友好（线下可执行）
- 避免过多标记（如张琪瑛4种标记）
- 避免技能"小作文"
- 可玩性 > 契合度（但有契合更佳）
- 避免双向debuff和"不如白板"的技能
- 考虑在不同模式下的适用性

### 4.3 对本项目的意义
- 20+武将的平衡性需要测试验证
- 新增武将应遵循简洁易懂的设计原则
- 需要工具支持武将平衡性测试（模拟大量对局统计胜率）

## 5. 测试策略

### 5.1 卡牌游戏专项测试
- **规则正确性测试**：验证每个技能在所有触发时机的行为
- **交互测试**：验证技能之间的组合效果
- **边界测试**：空牌堆、0血、多技能同时触发
- **Property-based测试**：使用Hypothesis生成随机游戏场景
- **AI测试**：验证AI在各种场景下的决策合理性

### 5.2 当前测试状况
- 1256个测试，75.71%覆盖率
- 使用pytest + hypothesis + ruff + mypy
- 但TUI测试覆盖度和网络测试不明

### 5.3 推荐测试框架
- **pytest** — 已在使用
- **pytest-asyncio** — 异步测试必需
- **pytest-textual-snapshot** — Textual快照测试
- **hypothesis** — 已在使用，扩大策略覆盖
- **pytest-xdist** — 并行测试加速

## 研究结论

### 核心发现
1. **三国杀技能系统极其复杂**：涉及多种触发时机、优先级规则、技能分类，需要强大的事件系统支撑
2. **开源实现的共同模式**：Lua/脚本化技能定义 + 事件触发器 + 断线重连
3. **FreeKill是最佳参考**：现代架构，活跃维护，完整的DIY框架
4. **平衡性需要工具支持**：模拟对局 + 统计分析
5. **测试策略需要专项化**：规则正确性、技能交互、边界、AI决策

### 映射到本项目的关键改进方向
- 参考FreeKill的触发器机制重构技能系统
- 实现完整的技能触发时机体系
- 修复转换技能（武圣/龙胆）的player.is_ai检查
- 添加武将平衡性测试工具
- 扩展测试覆盖到所有技能交互场景
